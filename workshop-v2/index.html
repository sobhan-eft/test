⚙️ XAMPP — اتاق تمرین شما در ۹۰ ثانیه

XAMPP سه چیز را یک‌جا نصب می‌کند: وب‌سرور (Apache)، دیتابیس (MySQL) و زبان سمت سرور (PHP). بدون این‌ها، فایل .php شما فقط یک متن است.

  1. از apachefriends.org دانلود و با تنظیمات پیش‌فرض نصب کنید.
  2. پنل کنترل را باز کنید و روبه‌روی Apache و MySQL دکمه Start بزنید — هر دو باید سبز شوند.
  3. پوشه‌ی پروژه را بسازید: C:\xampp\htdocs\mysite
  4. در مرورگر باز کنید: http://localhost/mysite
Apache روشن نمی‌شود؟ (Port 80 in use) معمولاً اسکایپ یا IIS پورت ۸۰ را گرفته. در XAMPP → Config → httpd.conf → مقدار Listen 80 را به Listen 8080 تغییر دهید، Apache را دوباره Start کنید و سایت را با http://localhost:8080/mysite باز کنید.

📐 نقشه‌ی مسیرها — این را حفظ کنید، نه چیز دیگر

# روی کامپیوتر شما (لوکال‌هاست) C:\xampp\htdocs\mysite\index.html → http://localhost/mysite # روی هاست واقعی public_html/index.html → https://yoursite.ir # قاعده‌ی طلایی htdocs (لوکال) == public_html (هاست)

در مک مسیر معمولاً /Applications/XAMPP/htdocs/ است.

۲۰٪ کلاس در نصب گیر می‌کنند — از قبل آرامشان کن: «اگه نصب طول کشید اصلاً نگران نباشین. تماشا کنین، بعداً با ویدیوی ضبط‌شده نصب می‌کنین. هیچ بخشی از کارگاه رو از دست نمی‌دین.» اگر خواستی سریع‌تر بروی: برای HTML/CSS خالص، VS Code + Live Server یا حتی CodePen کافی است — XAMPP فقط برای PHP و MySQL لازم می‌شود.

WHERE

فیلتر کردن سطرها. «فقط آن‌هایی که...»

ORDER BY

مرتب‌سازی. ASC صعودی، DESC نزولی.

LIMIT

فقط n تای اول. برای صفحه‌بندی.

الگوی همیشگی SELECT SELECT چه ستون‌هایی FROM کدام جدول WHERE چه شرطی ORDER BY مرتب بر چه LIMIT چند تا هر بخش اختیاری است جز دو تای اول. همین یک خط، کل SELECT است.
این اسلاید را با کلاس تعاملی کن. قبل از زدن هر دکمه، از آن‌ها بپرس نتیجه چه خواهد بود: «قبل از اینکه بزنم، حدس بزنین: اگه بگم پیام‌های خوانده‌نشده رو نشون بده، چند تا سطر برمی‌گرده؟ تو چت بنویسین.» این حدس‌زدن قبل از دیدن نتیجه، یادگیری SQL را چند برابر می‌کند. مخصوصاً روی GROUP BY که سخت‌ترین مفهوم این اسلاید است مکث کن.
نتایج این بخش از یک دیتاست نمونه‌ی درون‌صفحه محاسبه می‌شود تا بدون نیاز به سرور قابل نمایش باشد؛ خروجی دقیقاً همان چیزی است که MySQL برمی‌گرداند.

SELECT
    a.title       AS 'عنوان',
    c.name        AS 'دسته',
    a.views       AS 'بازدید'
FROM articles a
JOIN categories c ON a.category_id = c.id
ORDER BY a.views DESC;

🔌 PHP + دیتابیس — فرم تماسی که واقعاً کار می‌کند

<?php
// فقط این ۴ خط را روی هاست عوض می‌کنید
define('DB_HOST', 'localhost');
define('DB_NAME', 'mysite_db');
define('DB_USER', 'root');   // لوکال: root
define('DB_PASS', '');       // لوکال: خالی

function db() {
    static $pdo = null;
    if ($pdo === null) {
        $dsn = 'mysql:host='.DB_HOST
              .';dbname='.DB_NAME
              .';charset=utf8mb4';
        $pdo = new PDO($dsn, DB_USER, DB_PASS, [
            PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION,
            PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,
            PDO::ATTR_EMULATE_PREPARES => false,
        ]);
    }
    return $pdo;
}

پل ذهنی مهم: اینجا بگو که همین الگو پشت هر سایتی است که می‌شناسند. «این الگو رو یادتون باشه، چون همه‌چیزه. لیست محصولات دیجی‌کالا، فید اینستاگرام، لیست نوبت‌های یه کلینیک — همه‌ش همینه: یه SELECT، یه حلقه، یه قالب HTML. فقط بزرگ‌تر.»

💉 SQL Injection — چرا روی prepare اصرار کردیم

فرض کنید یک صفحه‌ی ورود دارید و کد را این‌طور نوشته‌اید (کاری که AI هم اگر نخواهید، ممکن است بکند):

✕ کد آسیب‌پذیر
$user = $_POST['user'];
$pass = $_POST['pass'];

// داده‌ی کاربر مستقیم چسبیده به دستور 👎
$sql = "SELECT * FROM users
        WHERE user = '$user'
          AND pass = '$pass'";

$row = db()->query($sql)->fetch();
if ($row) { /* ورود موفق */ }
✓ کد امن
$user = $_POST['user'];
$pass = $_POST['pass'];

// ساختار جداست، داده جدا 👍
$sql  = 'SELECT * FROM users
         WHERE user = ? AND pass = ?';
$stmt = db()->prepare($sql);
$stmt->execute([$user, $pass]);
$row = $stmt->fetch();

حالا ببینید مهاجم چه می‌نویسد

کاربر در فیلد رمز عبور این را تایپ می‌کند
' OR '1'='1
دستوری که در کد آسیب‌پذیر ساخته و اجرا می‌شود
SELECT * FROM users WHERE user = 'admin' AND pass = '' OR '1'='1'
نتیجهدسترسی کامل بدون دانستن رمز
شرط '1'='1' همیشه درست است → همه‌ی کاربران برمی‌گردند → اولین نفر وارد می‌شود.
در کد امن چه می‌شود؟ همان متن ' OR '1'='1 فقط به‌عنوان یک رمز عبور اشتباه در نظر گرفته می‌شود و ورود رد می‌شود. چون دیتابیس از قبل می‌داند کجای دستور «ساختار» است و کجا «داده».
پس در پرامپت‌هایتان همیشه بنویسید «حتماً از PDO با Prepared Statement استفاده کن، ورودی‌ها را با filter_var اعتبارسنجی کن و خروجی را با htmlspecialchars پاک‌سازی کن.»
همین یک جمله، تفاوت بین سایت امن و سایت هک‌شدنی است.
این اسلاید تو را از «مدرس AI» به مدرس مسئول تبدیل می‌کند. آرام و با تأکید اجرا کن. «من قرار نیست فقط از هوش مصنوعی تعریف کنم. باید اینم بدونین: اگه امنیت رو ازش نخواین، لزوماً بهتون نمی‌ده. و اون موقع یه سایت دارین که هر کسی می‌تونه واردش بشه.» برای مخاطب پزشکی یک جمله‌ی مهم اضافه کن: «اگه روزی سایتی بسازین که اطلاعات بیمار توشه، این دیگه فقط یه مسئله‌ی فنی نیست — مسئله‌ی اخلاقی و قانونیه.»

🚀 انتقال به هاست — چک‌لیست عملی

الف) فایل‌ها

  1. فایل‌های سایت را zip کنید — خودِ فایل‌ها را انتخاب کنید، نه پوشه‌ی بیرونی را.
  2. cPanel → File Manager → وارد public_html شوید.
  3. Upload → فایل zip را بکشید و رها کنید.
  4. روی فایل zip راست‌کلیک → Extract → سپس فایل zip را حذف کنید.
  5. مطمئن شوید index.html مستقیماً داخل public_html است.
اشتباهی که همه بار اول می‌کنند
✕ غلط public_html/mysite/index.html → باز می‌شود در: yoursite.ir/mysite ✓ درست public_html/index.html → باز می‌شود در: yoursite.ir

ب) دیتابیس

  1. در لوکال: phpMyAdmin → دیتابیس → تب Export → Go (یک فایل .sql دانلود می‌شود).
  2. در cPanel: بخش MySQL Databases → یک دیتابیس بسازید → یک کاربر بسازید → کاربر را با دسترسی All Privileges به دیتابیس وصل کنید.
  3. در cPanel: phpMyAdmin → دیتابیس جدید → تب Import → فایل .sql را آپلود کنید.
  4. در config.php چهار مقدار را عوض کنید:
// روی هاست، نام دیتابیس و کاربر معمولاً
// با پیشوند نام اکانت شما ساخته می‌شود
define('DB_NAME', 'username_mysite');
define('DB_USER', 'username_admin');
define('DB_PASS', 'رمزی که ساختید');

ج) SSL

cPanel → SSL/TLS Status → دامنه را انتخاب → Run AutoSSL → سپس Force HTTPS Redirect را روشن کنید.

۹۹٪ خطاهای «دیتابیس وصل نمی‌شود» از همین چهار خط config.php است. روی لوکال کاربر root با رمز خالی بود؛ روی هاست حتماً فرق دارد.
اگر دسترسی زنده به cPanel داری همین‌جا نشان بده. اگر نه، صادقانه بگو ضبط‌شده/اسکرین‌شات است. عمداً اشتباه پوشه را مرتکب شو و بعد درستش کن — یادگیری از اشتباه دیده‌شده چند برابر است. «بذارین من عمداً همون اشتباهی رو بکنم که همه بار اول می‌کنن...»

      ۱) چک‌لیست ۳۰ دقیقه قبل از شروع

      ۲) زمان‌بندی (۱۲۰ دقیقه)

      دقیقهبخشهدف
      ۰ – ۹خوش‌آمد، نمایش خروجی نهایی، نقشه راهانگیزه و تنظیم انتظار
      ۹ – ۱۷زیرساخت: چرخه‌ی درخواست، چه بخریمتصمیم‌گیری، نه حفظیات
      ۱۷ – ۳۳XAMPP، HTML و CSS با پیش‌نمایش زنده، زمین بازیدست به کیبورد شدن کلاس
      ۳۳ – ۴۷هوش مصنوعی: پرامپت دقیق، ساخت، اصلاحمهارت اصلی
      ۴۷ – ۸۵دیتابیس و SQL: CREATE، INSERT، SELECT، UPDATE، JOIN، PHP، امنیتعمیق‌ترین بخش کارگاه
      ۸۵ – ۹۵انتشار روی هاست، انتقال دیتابیس، SSL، جدول خطاهارسیدن به خروجی واقعی
      ۹۵ – ۱۲۰مسیر رایگان، برنامه ۳۰ روزه، پرسش و پاسختداوم بعد از کارگاه
      قانون طلایی زمان اگر دقیقه ۵۰ شد و هنوز وارد بخش دیتابیس نشده‌ای: زمین بازی (اسلاید ۹) و JOIN (اسلاید ۱۸) را حذف کن. این دو اولین کاندیدهای حذف‌اند. هرگز بخش امنیت (SQL Injection) را حذف نکن.

      ۳) جمله‌ی شروع (کلمه به کلمه)

      «سلام به همگی، خیلی خوش اومدین. من سبحان عفتی هستم، دانشجوی پزشکی شهید صدوقی یزد.

      یه سؤال قبل از شروع: چند نفرتون تا حالا فکر کردین "کاش یه سایت داشتم" ولی چون فکر می‌کردین باید برنامه‌نویسی بلد باشین بی‌خیال شدین؟ تو چت بنویسین.

      خب... تو دو ساعت آینده اون فکر رو کاملاً می‌ذاریم کنار. و یه خبر خوب: تمام کدهایی که امروز می‌بینین آماده‌ست، پس لازم نیست چیزی رو تند تایپ کنین یا عکس بگیرین.»

      ۴) نقشه‌ی اضطراری

      اگر این شداین کار را بکن
      اینترنت قطع شد یا AI جواب نداددکمه 📦 → بسته‌ی کدها را باز کن و بگو «این خروجی همون پرامپته که از قبل گرفتم». کلاس متوقف نمی‌شود.
      XAMPP کسی بالا نیامدبگو تماشا کند؛ با ویدیوی ضبط‌شده نصب می‌کند. اسلایدهای HTML/CSS پیش‌نمایش زنده دارند و بدون XAMPP هم قابل پیگیری‌اند.
      عقب افتادیزمین بازی و JOIN را حذف کن. اگر باز هم عقبی، بخش نمایش داده‌ها (اسلاید ۲۰) را فقط توضیح بده.
      جلو افتادیدر زمین بازی یک تمرین گروهی بده، یا یک پرامپت اضافه (دارک مود / سئو) را زنده اجرا کن.
      سؤالی پرسیدند که جوابش را نمی‌دانی«الان مطمئن نیستم، بعد از کلاس چک می‌کنم و جواب دقیق می‌دم.» — این اعتبارت را بالا می‌برد، نه پایین.
      یکی مدام سؤال خیلی تخصصی می‌پرسد«سؤال خوبیه ولی از سطح این کارگاه بالاتره — بعد از کلاس جداگانه در خدمتم.»
      دمو زنده خراب شدپنهانش نکن: «این دقیقاً همون چیزیه که برای شما هم پیش میاد» و جلوی کلاس با AI رفعش کن. بهترین لحظه‌ی آموزشی است.
      کلاس ساکت استسؤال بسته بپرس: «کی تونست صفحه‌ی phpMyAdmin رو ببینه؟ فقط بنویسین بله یا خیر.»

      ۵) هفت اصل ارائه‌ی خوب

      • نشان بده، بعد توضیح بده. اول خروجی را ببینند، بعد بفهمند چطور ساخته شد.
      • هر ۷ تا ۱۰ دقیقه یک تعامل. حتی یک «بله/خیر» در چت کافی است.
      • آهسته‌تر از چیزی که فکر می‌کنی حرف بزن. در ارائه‌ی آنلاین همه تندتر از حد لازم حرف می‌زنند.
      • موقع تایپ کردن، حرف بزن. سکوت طولانی یعنی از دست دادن مخاطب.
      • عدد بده. «سالی ۳۰ هزار تومان» مؤثرتر از «ارزان است» است.
      • هر بخش را با یک جمله جمع کن قبل از رفتن به بخش بعد.
      • محدودیت‌ها را هم بگو. مدرسی که فقط تعریف می‌کند، فروشنده به‌نظر می‌رسد.
